## 1. 设计动机与原则（pull 缺口与双通道闭环）

### 1.1 缺口

爬虫探索已下线（§COM-01 2026-08-09 甲方裁决，06 篇废弃处置 commit 0698512），内容分发现状只剩 **push 单通道**：内容节点定向推送链接卡片到展示节点（012）。用户只能看到**别人推到本节点**的卡片，**无法主动发现**网络中其他节点已收录的内容——缺 pull。

### 1.2 模型：整个网络都是分布式服务器（T6 网络即服务器）

每个节点收录了一批可验签的链接卡片（012 定向推送的收录结果）。检索 = 向好友链发起受限泛洪 query，**收录了匹配卡片的节点就地应答**（本机已验证的卡片即「索引」）——不需要爬虫、不需要中心索引服务器、不需要全文抓取；「整个网络都是分布式服务器」：任何节点既是自己卡片库的服务器，也是他人检索的中继与应答者。

### 1.3 push + pull 双通道闭环（与 012 协同图）

```
【① PUSH · 定向推送触达】content_push.md（012）：内容节点主动推，点对点直达（delivery=direct，ttl=1）

  内容节点 C ──POST /api/v2/push/card──▶ 展示节点 B（fail-closed 收录：验 creator_sig 后存卡片）
  (alice.example)   链接卡片 + creator_sig   (bob.example)
       │                                        │
       │（C 可将同一卡片逐目标签发推送到多个展示节点）        ▼
       │                                    展示节点 D (dave.example) 同样收录了一批卡片

【② PULL · 泛洪检索发现】本文件：用户主动查，受限泛洪查询好友链（T1 query/answer，≤6 跳 · fanout=16 · 防环）

  用户 ──"检索词"──▶ 检索发起节点 A ──T1 query(scope="content")──▶ 好友链 B / D / E…
                     (carol.example) ◀──T1 answer(cards[]+trust_weight+hops)──（各节点以**本地已收录**卡片应答）
                            │
                            └── 多来源聚合 + 去重 + T4 排序 ──▶ 返回结果列表给用户

【③ 闭环 · 点击跳转】用户点击 push 展示或 pull 检索结果中的卡片
  ──▶ 新开页面跳回内容节点：https://<creator_domain>/view/<content_key>
       （内容与广告主权留在内容节点，012 §6；展示/检索节点均不持有内容本体）
```

| # | 原则 | 协议落点 |
|---|---|---|
| P1 | 检索不复活爬虫 | §3/§5：仅查询**节点已收录的链接卡片**（title/summary 字段匹配），不回源抓取、不爬网页、不建全网索引（012 §5.4 极轻红线平移） |
| P2 | 受限泛洪非广播 | §2：完全复用 T1 纪律（好友链边、≤6 跳、fanout=16、forward_chain 防环），不向非好友广播 |
| P3 | 应答必须可验 | §4/§9：应答卡片 MUST 过 012 creator_sig 验签 + did:dns 指纹链（发起方独立重验，fail-closed） |
| P4 | 检索有独立配额 | §6：防滥用配额（发起配额 + 转发上限），与 T1 §8 同性质、非中心化限流 |
| P5 | 检索词隐私明示 | §8：检索词经 forward_chain 可见、非加密（与 DNS 查询同级）——「检索词非加密，敏感词慎用」 |
| P6 | 结果不裁决 | §5.4：返回去重排序后的多来源候选列表，不做内容审查/排名裁决（排序仅信任与路径信号，T4 引用）；点击与否由用户决定 |

### 1.4 与去中心化纪律的关系

- 检索是**节点本地发起 + 好友链受限泛洪**的去中心化发现机制，不依赖中心搜索引擎/索引集群/爬虫场。
- 防滥用（检索配额、转发上限、限频、黑名单）全部是**节点本地行为**（每节点自跑、不依赖中心化网关）——与 T1 §8「去中心化纪律」注同一口径：这里的「限流」指中心化网关限流，节点本地的防滥用配额是拓扑约束的一部分，不违反去中心化纪律（§6 详述）。
- 身份与防伪依赖 did:dns 三记录 + 统一 Ed25519 红线；身份记录解析**强制 DoH/DoT，禁明文 53**（架构红线，经 012 §4.3 验签链引用）。

## 2. 与 T1 泛洪协议的关系（核心：载荷语义主笔 + 域区分）

### 2.1 归属声明

T1（`flood_protocol.md`）§3 明文：`query`/`answer` 包类型特有字段的语义由对应领域草案定义（解析流程归 T6）。本文件即 **query/answer 在内容检索域的载荷语义主笔**——与 T6 解析域（DNS 解析查询）**并列的第二个 query 应用域**，两域经载荷内 `scope` 字段区分，T1 信封与包类型枚举**零改动、零重定义**：

1. `type` 恒为 `"query"` / `"answer"`（复用 T1 §3 包类型枚举，**不新增类型**）；
2. 信封 8 字段（`v`/`type`/`src_domain`/`ttl`/`query_id`/`nonce`/`forward_chain`/`signature`）**整体引用 T1 §2.1**，本文件不重定义任何信封字段；
3. `ttl` 发起时 ≤ **6**（T1 §4.1 query 跳数上限，`dns_flood_max_hops=6`，六度分隔）；fanout ≤ **16**（T1 §4.2）；
4. 防环/去重完全按 T1 §5（`forward_chain` 含自身丢弃、`query_id+nonce` 去重、链长 ≥ ttl+1 丢弃、-127 不转发不响应）；
5. `signature` 覆盖范围**引用 T9 §9.3.2 不重定义**（挑战码 + 双方域名 + `forward_chain` + T3 权重字段；JCS 规范化引 T1 §2.2/T9）；
6. 转发义务与 T1 §4.1 转发规则一致——泛洪引擎**按信封转发（payload 无关）**，载荷语义按 `scope` 分派（§5.2）。

### 2.2 与 T6 解析域的对照（`scope` 判别）

| 维度 | 解析域（T6，引用不重定义） | 内容检索域（本文件） |
|---|---|---|
| `payload.scope` | 缺省（无该字段即解析域，向后兼容 T6/02 篇现行语义） | **恒 `"content"`**（MUST，缺失/非 `"content"` 的载荷不按本文件处理） |
| 查什么 | `qname`/`qtype`（A/SRV/TXT 域名记录） | `keyword`/`content_types`（卡片检索词与类型过滤，§3） |
| 本地命中源 | `dns_hosts`（解析映射表） | 本节点**已收录链接卡片**（012 收录库，如 link_cards 表） |
| 应答载荷 | `candidates[]`（T1 §3.1.4/T4 候选） | `cards[]`（012 §3 链接卡片，§4） |
| 本地命中后 | 回传 answer，不再转发（T1 §4.1 规则 4） | 同左（回传 answer，不再转发该分支；§5.3） |
| 配额 | 系统解析不计配额（T1 §3） | **独立检索配额**（§6，本文件新定义） |

> **兼容性说明：** 不支持内容检索域的旧节点收到 `scope="content"` 的 query 时，因本地无命中而按 T1 规则继续 `ttl-1` 转发（payload 无关转发保证可达性）；其应答能力缺失不影响检索链路（发起方只聚合能应答的节点）。

## 3. 检索 query 载荷（`payload.scope = "content"`）

### 3.1 结构

```
{
  "scope": "content",
  "keyword": "<检索词, UTF-8, 去除首尾空白后 1~64 字符>",
  "content_types": ["article", "product", "post", "video"] | null,
  "cursor": "<分页游标, ASCII ≤128 | null>",
  "seen": ["<已见条目指纹, 16 字符 Base64URL, ≤16 条>"],
  "requester_domain": "<请求方域名, ASCII, 同信封 src_domain>"
}
```

载荷置于 T1 §2.1 信封的 `payload` 字段内；query 包整体（信封+载荷）序列化后 **MUST ≤ 4 KiB**。

### 3.2 字段定义

| 字段 | 类型 | 必选 | 约束 | 含义 |
|----|------|------|------|------|
| `scope` | str | 是 | 恒 `"content"` | 检索域判别（§2.2）；本文件新增 |
| `keyword` | str | 是 | UTF-8，trim 后 1~64 字符，禁控制字符 | 检索词；匹配对象为卡片 `title`/`summary`（012 §3.2，不解析内容文本——012 §5.4 红线平移） |
| `content_types` | str[]/null | 否 | 元素 ∈ `article`/`product`/`post`/`video`（**012 §3.2 枚举引用**），≤4 个，去重 | 内容类型过滤；`null` = 不过滤；`ad_slot` 卡片**恒不参与**内容检索（§9.3） |
| `cursor` | str/null | 否 | ASCII ≤128，不透明 | 分页游标：**发起节点本地不透明编码**（如本节点上一轮应答 `next_cursor` 原样回传）；**转发/应答节点 MUST NOT 解析、不得据其过滤**（跨节点分页由 `seen` 排除集驱动） |
| `seen` | str[] | 否 | 每项 16 字符 = `Base64URL(SHA-256(creator_domain + "\n" + content_key)[0:12])`，≤16 条 | 去重集（排除集）：应答节点 MUST 从结果中排除指纹命中项（同键卡片不再回传）；上限 16 防包膨胀（用户翻页时由发起节点滚动更新，§5.1） |
| `requester_domain` | str | 是 | ASCII，= 信封 `src_domain` | 请求方域名（T1 §3.1.3 同名字段引用，语义不变） |

### 3.3 匹配语义（应答节点本地）

- 匹配对象：本节点已收录卡片（012 §5 fail-closed 校验后收录的存储）的 `title` 与 `summary` 字段；
- 匹配规则：大小写不敏感的**子串匹配**（最小可用语义，本版 v0.2 不定型分词/模糊/相关性评分——守「方向驱动分阶段细化」）；
- 过滤条件：`card_type == "content"`（MUST，§9.3）、`content_types` 含该卡 `content_type`（若非 null）、未过期（`exp > now`）、本地展示开关开启（`is_listed` 类开关，012 §5.5 口径）；
- 结果裁剪：本地命中按 `(trust_weight DESC, hops=0, exp−now DESC)` 预排后取**前 5 条**入 answer（§4.3 单包上限）。

## 4. 检索 answer 载荷（链接卡片应答）

### 4.1 结构

```
{
  "scope": "content",
  "cards": [ <012 链接卡片, §3 of content_push.md, ≤5 张> ],
  "trust_weight": <路径权重 = min(链上各转发者权重), 引用 T3 §4>,
  "hops": <回传路径总跳数>,
  "cache_hit": <bool, 是否缓存命中代答>,
  "cached_at": <缓存写入时间 Unix 秒 | null, 仅 cache_hit=true 时非 null>
}
```

answer 包整体（信封+载荷）序列化后 **MUST ≤ 16 KiB**；沿 `forward_chain` 逆向回传（T1 §6.1）。

### 4.2 字段定义

| 字段 | 类型 | 必选 | 含义 | 来源 |
|----|------|------|------|------|
| `scope` | str | 是 | 恒 `"content"`（与 query 对应） | 本文件 |
| `cards` | obj[] | 是 | 012 §3.1 链接卡片数组（**格式/字段/长度约束整体引用 content_push.md §3，不重定义**）；每张卡片自带 `creator_sig`；**≤5 张**（MUST，防单包膨胀与单节点刷屏） | 012 §3 |
| `trust_weight` | int | 是 | 路径权重 = min(查询链上各转发者 `contacts.trust_weight`)，**引用 T3 §4 min 保守聚合与 T1 §3.1.4 同名字段**；MUST 纳入 T9 §9.3.2 签名覆盖（引用不重定义） | T1/T3/T9 |
| `hops` | int | 是 | 回传路径总跳数（T1 §3.1.4 同名字段引用） | T1 |
| `cache_hit` | bool | 是 | 本应答是否来自该节点**检索缓存**命中代答（§7）；缓存命中 MUST 置 `true`，不得伪装为即时检索结果 | 本文件 |
| `cached_at` | int/null | 是 | 缓存写入时间 Unix 秒；`cache_hit=false` 时恒 `null`。发起方据此判定结果新鲜度（本地策略可丢弃过旧缓存应答） | 本文件 |

### 4.3 卡片验签绑定（关键：target_domain = 应答节点域名）

012 §4.3 卡片级签名输入为 `JCS(card 除 creator_sig 外全部字段) + "\n" + target_domain`，其中 `target_domain` 是卡片**收录时的推送目标**（接收展示节点）。检索应答中：

1. 应答节点（answer 信封 `src_domain` = 应答节点域名）**只持有以自己为收录目标**的卡片（012 §5.2-4 `target_mismatch` fail-closed 拒收保证）；
2. 因此发起方重验每张卡片时，验签输入第二行取 **`answer` 信封 `src_domain`（即应答节点域名）**；
3. 发起方校验：`card.creator_domain` 有效、`creator_fp` 与 `did:dns:v=1` 指纹一致、以 `did:dns:pk` 验 `creator_sig`（覆盖 `…\n + answer.src_domain`）、`card.exp > now`——**任一失败丢弃该卡片**（fail-closed，§9 详述）；
4. 012 §5.3-3 的 `iat ±5min` 新鲜度属**收录时刻**校验（应答节点收录时已执行）；检索时刻只复验签名链与未过期，不重复收录时刻的时间校验。

## 5. 节点行为契约（发起 / 中转 / 应答 / 聚合）

### 5.1 发起节点（用户 → 本节点 → 泛洪 → 聚合返回）

```
① 本地 API 收到检索请求（§10.1，requireAuth）
② 配额检查（§6）：本日发起次数 < cq_quota_daily，超限 → 429（不泛洪）
③ 结果缓存检查（§7.1）：命中未过期 → 直接返回缓存（from_cache=true，不泛洪——防重复泛洪）
④ 构造 query（§3）：keyword 归一化 + cursor + seen（首页为空/翻页为已聚合条目指纹）
⑤ 本地卡片检索（§3.3 匹配规则查本节点收录库，本地命中【不抑制】泛洪——
   检索是聚合语义非定位语义，与 T6 解析「本地命中即返回」不同）
⑥ 按 T1 §4 并行 POST 给 ≤ fanout 个未拉黑好友（泛洪引擎接口，§10.2）
⑦ 等待 cq_query_timeout_ms 聚合窗口，收集同 query_id 的全部 answer
⑧ 逐张卡片过 §9 防投毒管线（creator_sig 重验 + push_blacklist + -127 过滤）
⑨ 聚合去重排序（§5.4：按 (creator_domain, content_key) 去重 + T4 排序 + 每来源限条数）
⑩ 写结果缓存（§7.1），返回结果列表 + next_cursor + from_cache=false + quota_remaining
```

### 5.2 中转节点（payload 无关转发 + 内容域分派）

- **转发层（T1 引用，与解析域共用同一泛洪引擎）**：限频（每好友入站 ≤30 次/分）→ 防环（`forward_chain` 含自身丢弃 / `query_id+nonce` 去重 / 链长检查）→ 黑名单（-127 不转发不响应）→ `ttl-1` 转发给未拉黑好友——全部按 T1 §4.1/§5 执行，不因 `scope` 不同而异；
- **内容域分派（本文件新增）**：收到 `scope="content"` 的 query 时——
  1. **缓存命中**（§7.2）：`(keyword, content_types)` 命中未过期 → 构造 answer（`cache_hit=true` + `cached_at`）回传，**该分支不再转发**（缓存吸收，防重复泛洪）；仍按 T1 去重表登记该 `query_id`；
  2. **本地卡片命中**（≥1 张匹配，§3.3）：回传 answer（`cache_hit=false`），该分支不再转发（与 T1 §4.1 规则 4「本地命中则回传」一致）；
  3. **无命中且 `ttl-1 > 0`**：追加自身域名到 `forward_chain`，转发（受 §6.2 转发上限约束）；
  4. **到跳数上限无命中**：静默不响应（T1 §6.1 同口径）。

### 5.3 应答节点

- 应答卡片 MUST 来自本节点**已收录且验签通过**的存储（012 §5 收录管线产物；不收录未验签卡片，故不存在「先应答后补验」路径）；
- 按 §3.3 过滤裁剪后取前 5 张；answer 信封由应答节点自身签名（`src_domain` = 应答节点域名，覆盖引 T9 §9.3.2）；`trust_weight` 按当前查询链 min 聚合（T3 §4，应答方不加入链）；
- answer 逆向回传途中，**链上中转节点仅可写「收录目标为本节点」的卡片入检索缓存**（§7.2，v0.2 收紧：本节点自己收录且验签通过的应答卡片 MAY 缓存以备命中代答；**他站应答卡片（`creator_sig` 验签第二行 = 应答节点域名 ≠ 本节点）MUST NOT 写入本地检索缓存**——经本节点代答必被发起方按 §9.1-4 重验丢弃，§4.3 签名绑定语义）。

### 5.4 聚合、去重与排序（发起节点）

| 步骤 | 规则 |
|---|---|
| 合并 | 本地命中（步骤⑤）+ 全部 answer 的 `cards[]` 合并 |
| 去重 | 按 `(creator_domain, content_key)`（012 §3.3 全网唯一定位键引用）去重；同键多来源保留排序最优者，可标注来源数供展示 |
| 验签 | 逐张过 §9 管线（fail-closed，未过即丢弃） |
| 排序 | **排序键 = `(trust_weight DESC, hops ASC, exp−now DESC)`**——沿用 T4 §3.1 排序键结构（**引用不重定义**），其中 T4 的 `TTL DESC` 键在卡片语境映射为**卡片剩余有效期**；同分以 `(creator_domain, content_key)` 字典序稳定排序 |
| 限条数 | **每应答来源域名计入聚合结果的卡片 ≤ 5 张**（MUST，防单节点刷屏——与单包上限一致）；最终列表按 `limit` 截断（默认 20，≤30） |
| 分页 | 返回 `next_cursor`（发起节点本地不透明编码）；用户翻页 → 以已聚合条目指纹更新 `seen` 后续查（§3.2） |

## 6. 独立检索配额（防检索洪水；与 T1/FR11 同性质）

### 6.1 为什么 T1 §8 每日 3 次不适用

T1 §8 的「每日 3 次」约束**用户自主广播类**泛洪（`publish` + 用户触发的 `count`）；`query` 属查询类（T1 §3 配额计入列「否」）。检索是**用户主动发起的 query**，频率远高于 DNS 解析（搜索习惯为每日一二十次量级，解析随连接触发无独立配额）——既不能按 T6 解析域零配额放任（检索洪水放大风险：1 次检索 = 1 棵 fanout≤16、≤6 跳的泛洪树），也不应提高 T1 §8 已会签的 3 次口径（不修改 T1 条款）。故本文件定义**独立检索配额**（新增并列项，不改 T1 §8）。

### 6.2 配额口径

| 规则 | 建议默认 | 说明 |
|---|---|---|
| 发起配额 `cq_quota_daily` | **20 次/发起节点/日** | 节点本地自守：超限拒绝本地 API 请求（429 `quota_exceeded`，§10.3），**不发起泛洪**；具体数值会签时可钉死，节点本地可调（量级约束：防滥用，不限正常使用） |
| 转发上限 `cq_forward_per_min` | **10 次/节点/分钟** | 每节点每分钟转发 `scope="content"` 的 query 包上限（本地策略），超限**静默丢弃**——抑制检索泛洪树的级联放大 |
| 入站限频 | 每好友 30 次/分 | **引用 T1 §4.1/FR11 入站口径**（包级，与解析域共用，不重定义） |
| 跳数/出度 | ≤6 跳 / fanout=16 | **引用 T1 §4**（不另设检索专用值） |
| 邻居超限观测 | 持续远超发起配额口径 | 观测到同一 `src_domain` 的内容检索频率持续远超配额口径（视为滥用），MAY 按 T1 §8/FR11 同性质处置：自动拉黑 -127（不转发其包、不响应其查询，T3 §6） |

### 6.3 性质声明（措辞对齐 T1 §8）

> **去中心化纪律:** 上述检索配额与转发上限是**节点本地**防滥用行为（每节点自跑、不依赖中心化网关），与 T1 §8/FR11 同性质——这里的「限流」指中心化网关限流，节点本地的配额/限频是拓扑约束的一部分，**不违反去中心化纪律**（T1 §8 注原文口径）。

## 7. 结果缓存（防重复泛洪）

### 7.1 发起节点结果缓存

- 缓存键：`(归一化 keyword, content_types 集合)`；缓存值：聚合结果列表 + 写入时间；
- TTL：`cq_cache_ttl`，**允许区间 60~300 秒（短缓存），默认 120 秒**（会签可钉死）——足够挡住用户短时内反复搜索同一词的重复泛洪，又不过度陈旧；
- 命中未过期 → 直接返回（`from_cache=true`，**不发起泛洪**）；`cursor` 翻页在缓存上推进，缓存未过期期间翻页不泛洪；
- 过期 → 正常泛洪并刷新缓存。

### 7.2 链上节点缓存（仅限本节点收录卡片；forward_chain 上节点可应答缓存命中）

- **写入（仅限本节点卡片，v0.2 收紧）**：中转节点 MAY 以 `(keyword, content_types) → cards` 写本地检索缓存（TTL 同 §7.1 上限口径），但**仅可缓存经本节点 012 验签管线校验通过且收录目标为本节点的卡片**——即 `creator_sig` 验签输入第二行 = 本节点域名的卡片（§4.3，**本节点自己收录的应答卡片**；典型写入时机：本节点以自身收录卡片构造 answer 应答时缓存自己的应答结果）；**answer 逆向流经的转发他站卡片（第二行 = 其他节点域名）MUST NOT 写入本地检索缓存**（X-QA FAIL 项修订，理由见本节设计说明）；缓存对象同时**仅限已过 012 验签管线的卡片**（缓存投毒防线，§9）；
- **命中代答（仅返回本节点卡片）**：后续同关键词 query 流经且缓存未过期 → **仅以「收录目标为本节点」的缓存卡片**直接构造 answer 回传（此类卡片以本节点名义应答：`answer.src_domain` = 本节点域名，与卡片 `creator_sig` 验签第二行一致，发起方按 §9.1-4 重验可通过），标注 **`cache_hit=true` + `cached_at=<缓存写入时间>`**（MUST，不得伪装为即时检索结果）；该分支不再转发（**缓存吸收**：泛洪树在该分支被截断，防重复泛洪）；
- **新鲜度边界**：缓存应答的时效以 `cached_at` 明示；发起方本地策略可过滤 `now − cached_at` 过大的应答（建议默认接受 TTL 窗口内的缓存应答）；
- **不豁免重验**：发起方对缓存应答中的卡片**仍逐张独立重验**（§9，fail-closed——缓存不构成信任来源）；缓存应答的 `trust_weight` 按当前查询链 min 聚合（T3 §4），不携带原应答权重。
- **设计说明（为何链上缓存仅限本节点卡片，v0.2）**：§4.3 签名绑定语义决定卡片 `creator_sig` 验签输入第二行 = `answer.src_domain`（卡片只在**收录目标节点**的应答中有效，防跨节点重放）。若允许中转节点 X 缓存 answer 逆向流经的他站卡片（签给应答节点 B）并命中代答，则 `answer.src_domain=X` 与卡片验签第二行 B 不一致，发起方按 §9.1-4 重验必失败 → 整包卡片 fail-closed 丢弃；且该分支被「缓存吸收」截断不再转发，B 的真实应答亦无法流经该分支——同关键词查询经该分支在 TTL 窗口内**零有效结果**。故链上缓存范围 MUST 限于「收录目标为本节点」的卡片（以本节点名义应答、发起方重验可通过），消除 §7.2 与 §4.3 的内在矛盾（X-QA 验收报告第 5 项，唯一 FAIL）。

## 8. 隐私明示（检索词可见性）

| # | 事实 | 说明 |
|---|---|---|
| 1 | **检索词非加密** | `keyword` 在 query 载荷中明文传播：`forward_chain` 上所有节点及其转发的好友**均可见**检索词与发起方 `src_domain`——与 DNS 查询（`qname` 明文经转发链，T6/T1 现状）**同级暴露** |
| 2 | **为什么不能加密** | 中间节点必须能读取检索词才能本地匹配与缓存代答——端到端加密检索与去中心化好友链检索机理矛盾；敏感检索需求的加密方案（如 PIR）不在阶段一范围 |
| 3 | **明示口径（MUST 呈现）** | 本地检索端点/节点 UI MUST 向用户明示：**「检索词非加密，敏感词慎用」**（§10.1 响应或 UI 提示任一形式） |
| 4 | 行为画像风险 | 链上/缓存节点可获知「谁在检索什么」；RECOMMENDED 节点不落盘 `requester → keyword` 关联日志（节点本地策略，非协议强制） |

## 9. 防投毒与结果过滤（fail-closed）

### 9.1 卡片验签管线（引用 012，不重定义）

发起方对聚合结果中的**每张**卡片执行（任一失败 → 丢弃该卡片，不展示、不进缓存）：

| # | 校验项 | 引用 |
|---|---|---|
| 1 | 卡片结构/字段/长度约束（title≤120、summary≤300、`content_key` 字符集等） | 012 §3.2 |
| 2 | DoH/DoT 解析 `card.creator_domain` 的 did:dns 三记录（v=1 指纹 / pk kty=ed25519 / black 黑名单）——**强制加密 DNS，禁明文 53** | 012 §4.3/§5.3-5（经 012 引用 did-dns §2/§3） |
| 3 | `card.creator_fp == did:dns:v=1 的 fp` | 012 §5.3-6 |
| 4 | `creator_sig` 验签（输入第二行 = `answer.src_domain`，§4.3） | 012 §4.3 |
| 5 | `card.exp > now`（未过期） | 012 §5.3-3 |
| 6 | 信封验签（answer 包 T9 §9.3.2 覆盖，公钥 = 解析 `answer.src_domain` 的 `did:dns:pk`） | T1 §7 / T9 §9.3.2 |

> **fail-closed 红线：** 无法校验（解析失败/无 DNSSEC 且指纹链断裂/签名不过）即丢弃；**禁止**「先展示后补验」（012 §5.3 红线平移，修复并阻断节点仓 12 篇原缺陷 7.1 型风险在检索链路复发）。

### 9.2 黑名单与负权重过滤

| 过滤 | 时机 | 引用 |
|---|---|---|
| 发起方本地 `push_blacklist` 含 `card.creator_domain` | 聚合时过滤（拒看即本地 opt-out） | 012 §7（抗屏蔽三原则：本地行为，不影响他节点） |
| T3 `-127`：`creator_domain` 或 `answer.src_domain` 权重 = -127 | 过滤（不转发其包、不响应其查询、候选过滤） | T3 §6（引用不重定义） |
| 应答节点本地 `push_blacklist` | 收录时已下架（`is_listed=false`），本地匹配天然排除 | 012 §7/§5.5 |

### 9.3 结果集约束

- **`ad_slot` 卡片不参与内容检索**（MUST）：广告位是节点版面经营（012 §8），混入检索结果构成刷屏通道；应答节点匹配与发起方聚合双重排除 `card_type != "content"` 的卡片；
- **每来源限条数**：每应答来源域名 ≤5 张（§5.4）——单节点即使收录巨量匹配卡片也无法刷屏占用结果列表；
- **排序防操纵**：排序信号只有信任权重（本地维护，T3）与路径跳数（拓扑事实）——无点击/热度等可刷信号（本版 v0.2 不引入，防 SEO 型投毒）。

## 10. 端点契约

### 10.1 本地检索发起端点（用户 → 本节点，跨仓新契约端点）

| 项 | 定义 |
|---|---|
| 端点 | `POST /api/v2/query/content`（进入 `/api/v2/` 命名空间，与 012 `/api/v2/push/*` 同族；**必选**） |
| 认证 | requireAuth（本地用户会话；发起配额按节点计，§6.2） |
| 请求体 | `{"keyword": "<1~64 UTF-8>", "content_types": ["article",…]\|null, "cursor": "<string\|null>", "limit": <int, 1~30, 默认 20>}` |
| 响应体（200） | `{"results": [{"card": <012 卡片原文>, "hops": <int>, "trust_weight": <int>, "source": "<应答来源域名>", "cache_hit": <bool>}…], "next_cursor": "<string\|null>", "from_cache": <bool>, "answers": <收到 answer 数>, "elapsed_ms": <int>, "quota_remaining": <int>, "privacy_notice": "检索词非加密，敏感词慎用"}`（`privacy_notice` MUST 原文携带，§8） |
| 降级语义 | `cq_enabled=false`（泛洪引擎未就绪/未启用，§11）→ **503** `{"error":"not_ready"}`（fail-closed，不静默返回空结果伪装成功） |

### 10.2 泛洪引擎接口（节点间，复用 T1 wire，不新增端点）

- 检索 query/answer 包即 **T1 §2 信封 + §3 query/answer 包类型**（载荷按本文件 §3/§4）；
- 传输承载**整体引用 T1 §9**：v1 走 HTTPS 直连好友泛洪入站端点（`POST /api/dns/query`，02 篇 §3.3/§5.2 规划口径），E06 WS 常驻通道（8082）落地后优先走 WS——检索包与解析包**同一入站端点**，由泛洪引擎按 `payload.scope` 分派（§5.2），**不新增节点间端点**（零额外跨仓端点负担）；
- 展示节点聚合返回：多来源 answer 经 §5.4 聚合去重排序后经 §10.1 单一响应返回（多候选合并去重；卡片流 UI 数据口 `GET /api/cards` 为节点本地端口径，012 会签裁定，不入本契约）。

### 10.3 响应码契约（本地端点）

| 状态码 | 场景 | 响应体 |
|---|---|---|
| 200 | 检索完成（含零结果）/ 缓存命中 | §10.1 响应体（`from_cache` 区分） |
| 400 | `keyword` 空/超长/含控制字符、`content_types` 枚举非法、`limit` 越界 | `{"error":"invalid_query","detail":"..."}` |
| 401 | 未认证 | `{"error":"unauthorized"}` |
| 429 | 本日发起配额用尽（§6.2） | `{"error":"quota_exceeded","retry_after_ms":<至次日零点>}` |
| 503 | 检索未启用/泛洪引擎未就绪（fail-closed） | `{"error":"not_ready"}` |

## 13. 安全考量汇总（fail-closed）

| 威胁 | 缓解 | 落点 |
|---|---|---|
| 伪造卡片（冒名 creator_domain 投毒结果） | `creator_sig` + did:dns fp 指纹链 + DoH/DoT；发起方逐张独立重验 | §4.3、§9.1 |
| 卡片跨节点重放（为他站签的卡混入） | 验签输入第二行 = `answer.src_domain` 绑定（卡片只在收录目标节点应答中有效） | §4.3 |
| 检索洪水（恶意高频发起检索） | 独立发起配额 + 转发上限 + T1 跳数/fanout/入站限频；邻居超限可 -127 | §6（引 T1 §4/§8、FR11） |
| 查询/应答重放 | `query_id + nonce` 去重表（T9 §9.3.1 一次性约束） | §5.2（引 T1 §5.2） |
| 缓存投毒 | 仅缓存已验签卡片 + 短 TTL + `cache_hit`/`cached_at` 透明标注 + 发起方重验不豁免 | §7、§9.1 |
| 单节点刷屏（巨量匹配占满结果） | 每包 ≤5 张 + 每来源聚合 ≤5 张 + `ad_slot` 排除 | §4.1、§5.4、§9.3 |
| 巨型包 | query ≤4 KiB（keyword≤64/seen≤16）、answer ≤16 KiB（cards≤5，卡片 ≤2KiB/张引 012 §3.1） | §3.1、§4.1 |
| 黑名单来源 | T3 -127 不转发不响应 + `push_blacklist` 过滤（双机制独立生效，012 §7.2 口径） | §9.2 |
| 检索词隐私 | 明示「检索词非加密，敏感词慎用」（与 DNS 查询同级暴露） | §8 |
| 中间人 | 强制 HTTPS + 强制 DoH/DoT（禁明文 53，架构红线） | §9.1（经 012 引用） |

> **去中心化纪律:** 上述防线全部为节点本地行为（验签/配额/缓存/过滤），无中心化网关、无注册、无 CA——与 T1 §8/012 §12 同一纪律。
