## 1. 设计动机：去中心化防污染（运营期机理）

KirinNet 用**两套机理**防投毒/防污染，本文件管**第二套（运营期，去中心化、持续）**：

| 机理 | 定位 | 时段 | 文件 |
|---|---|---|---|
| 引导期计数（T8） | 防投毒（一次性阀门） | 引导期 | T8 |
| **运营期信任权重（本文件 T3）** | **防污染（持续机理）** | 运营期（T8 开关 OFF 后接管） | **本文件** |

**社交节点自我修复的防污染解析（§0 决策）:** 信任权重体系通过 IM 列表好友分级 + 钱包级负权重降低恶意域名解析分数，实现**去中心化**的社交节点自我修复，**不依赖中心化权威 / CA / 注册系统**。

**与去中心化纪律:** 信任权重是节点本地维护 + 好友链传播的去中心化机理，每个用户自跑节点、自行维护好友权重，符合 §6「去中心化原则」。

## 2. IM 列表结构（dns_hosts + contacts）

### 2.1 dns_hosts 表（解析网络，承载三类条目）

**IM 列表即解析网络**（02 篇 FR5）：`dns_hosts` 表承载 ① 好友条目（来自 IM `announce`）② 常用网址（手动添加）③ 泛洪应答缓存。条目字段（与节点 02 篇 §4 对齐）：

| 字段 | 类型 | 含义 | 约束 |
|---|---|---|---|
| `domain` | str | 域名 | ASCII |
| `record_type` | enum | A / SRV / TXT(did:dns:) | 三类 |
| `content` | str | IP / host:port / did:dns: 串 | |
| `trust_weight` | int | 信任权重 | **-127~100**（见 §3） |
| `source` | enum | manual / friend / flood | manual 永不过期；friend/flood 按 TTL 过期 |
| `ttl` | int | TTL 秒 | 默认 300 |
| `expires_at` | int/null | 过期 Unix 秒；null = 永不过期（手动条目） | |
| `via_chain` | str | 到达路径（转发链 JSON，承载权重携带） | 默认 `[]` |

### 2.2 contacts 表（好友关系，承载边权重）

`contacts` 表的 `trust_weight` 字段（02 篇 §4 迁移）承载**好友边权重**（好友分级）：

| 字段 | 类型 | 含义 | 约束 |
|---|---|---|---|
| `trust_weight` | int | 好友信任权重 | **-127~100**（见 §3），手动维护分级 |

> **依据:** 节点 02 篇 §4 `ALTER TABLE contacts ADD COLUMN trust_weight INTEGER DEFAULT 0;`

### 2.3 IM 列表 = 解析网络节点图（02 篇 §6）

- IM 列表（contacts）就是解析网络的**节点图**；好友关系 → 泛洪边（T1 转发关系）。
- 拉黑（trust_weight=-127）**双向生效**：A 拉黑 B → B 不转发 A 的包、不响应 A 的查询（02 篇 §6 + FR7/FR11）。

## 3. 好友分级与取值域（trust_weight -127~100）

### 3.1 取值域

- **`trust_weight ∈ [-127, 100]`**（有符号 int8 范围），与节点 02 篇 `dns_hosts.trust_weight` / `contacts.trust_weight` 一致（FR5/FR7）。
- **默认值 0**（新好友/新条目初始权重）。

### 3.2 好友分级（建议语义，用户可自行调整）

| 权重区间 | 分级 | 语义 | 解析行为 |
|---|---|---|---|
| **-127** | **黑名单（拉黑）** | 不信任/恶意 | 不转发其包、不响应其查询、不计数（T8）/其候选过滤（02 篇 FR7/FR11） |
| [-126, -1] | **负权重（不信任）** | 可疑/降低优先 | 候选分数降低（排序靠后，T4）；钱包级负权重降低解析分数（§5） |
| **0** | **默认（中立）** | 新好友/未评级 | 正常参与解析 |
| [1, 99] | **正权重（信任）** | 常用好友/可信网址 | 候选分数提升 |
| **100** | **最高信任** | 自身/极信任节点 | 候选最高优先（通常自身域名=100） |

### 3.3 维护方式（§0 决策）

- **IM 列表手动维护权重**（好友 + 常用网址）：用户通过节点设置面板手动调整 `contacts.trust_weight` / `dns_hosts.trust_weight`。
- **好友间权重不同**：每对好友关系独立权重（非全网统一）。
- **转发链天然带权重分**：路径权重 = min(链上各转发者权重)（§4，保守聚合）。

## 4. 转发链权重携带（min 保守聚合，防信任冲刷）

### 4.1 路径权重 = min(链上各转发者权重)

**核心规则（与节点 02 篇 FR7 一致）:**

```
路径权重(path_weight) = min(forward_chain 中各转发者的 contacts.trust_weight)
```

- 转发链上每个节点的权重取 `min`（保守聚合），**非** Σ/avg/max。
- **防信任冲刷:** 恶意节点 A（高权重）经恶意中转 B（低权重）转发 → 路径权重被 B 拉低到 B 的权重，防止高权重节点为低权重内容"洗白"。

### 4.2 answer 包携带权重（T1 §3.1.4 + 本文件）

`answer` 包（T1 §3.1.4）的 `trust_weight` 字段即**路径权重**（min 聚合结果），候选 `candidates[].trust_weight` 为各候选的本地权重（dns_hosts.trust_weight）。两者均**MUST 纳入 T9 签名覆盖范围**（T9 §9.3.2 第 5 项，防权重篡改）。

### 4.3 权重携带流程

```
发起方 A (weight=80)
   │ query (forward_chain=[A], path_weight=80)
   ▼
好友 B (weight=60) 本地 miss → 转发
   │ forward_chain=[A,B], path_weight=min(80,60)=60
   ▼
好友 C (weight=90) 本地命中 → answer
   │ answer(trust_weight=min(80,60)=60, candidates=[...])
   │ （注意：path_weight 取链上 min，不含 C 自身转发权重；C 作为应答方不加入链）
   ▼
A 聚合 answer（trust_weight=60）
```

> **签名覆盖:** 上述 `forward_chain` 与 `trust_weight` 字段在 answer 包签名时 MUST 纳入覆盖（T9 §9.3.2），防中转篡改权重。**引用 T9 草案·未会签·单边定稿无效**。

## 5. 钱包级负权重（防污染解析）

### 5.1 机制（§0 决策）

- **钱包级负权重**：用户可对特定**钱包地址**关联的域名施加负权重，降低其解析分数。
- **目的**：社交节点自我修复的防污染解析——当某钱包（恶意/欺诈）被多人标记负权重，其关联域名解析分数全网自然下降，无需中心化封禁。

### 5.2 钱包地址编码（引用 T2，不自行定义）

- 钱包地址的**编码格式**（如 XRP 优先，§0 身份模型）**归 T2 定义**，本文件**引用 T2 不重定义**。
- 本文件仅定义：钱包地址 → 域名映射的**负权重施加语义**（用户对钱包地址 X 关联的所有域名施加 `trust_weight` 负值，降低其候选分数）。

### 5.3 与域名级负权重的关系

| 层级 | 作用对象 | 字段 | 来源 |
|---|---|---|---|
| **域名级负权重** | 单个域名 | `dns_hosts.trust_weight`（负值/-127） | 手动 / 泛洪缓存（02 篇 FR7） |
| **钱包级负权重** | 钱包地址关联的所有域名 | 钱包→域名映射 + 负权重（引用 T2 编码） | 用户手动标记（§0 决策） |

- **聚合**：域名候选最终分数 = 域名级权重 + 钱包级权重（若该域名关联被标记的钱包）的**保守聚合**（倾向取 min，防冲刷）。

## 6. -127 黑名单（与 FR7/FR11 一致）

### 6.1 黑名单语义

- **`trust_weight = -127`** 即**黑名单**（拉黑）—— 取值域下限，与节点 02 篇 FR7/FR11 一致。

### 6.2 黑名单行为（双向生效，02 篇 §6 + FR7/FR11）

| 行为 | 说明 |
|---|---|
| **不转发其包** | 黑名单节点（A 拉黑 B）→ A 不转发 B 的任何泛洪包（query/answer/announce/count/publish） |
| **不响应其查询** | A 不响应 B 的 query（B 解析失败，社交隔离） |
| **不计数其回执** | T8 计数时黑名单节点的 count 回执不计入累计（§3.2） |
| **候选过滤** | B 的域名候选在 A 的解析结果中被过滤（不返回或返回 trust_weight=-127 供客户端判断） |
| **配额超限自动拉黑** | 每日泛洪超 3 次（T1 §8）→ 自动 trust_weight=-127（02 篇 FR11） |

### 6.3 黑名单传播（非全网广播）

- 黑名单是**节点本地**状态（A 拉黑 B 仅影响 A 的行为），**不强制全网传播**（守去中心化，每节点自行决定信任）。
- 钱包级负权重可通过泛洪在好友链传播（§5），但传播受 min 聚合约束（防冲刷）。

## 7. 与 T4/T8 的互引（共管切换点）

### 7.1 T4 消费 T3 权重（排序）

- T4（多候选解析）的排序键 `(trust_weight DESC, hops ASC, TTL DESC)`（02 篇 FR7）**消费** T3 权重值；本文件定义权重值，T4 定义排序应用。
- 候选 `trust_weight` = 路径权重（min 聚合，§4）或本地权重（dns_hosts.trust_weight），T4 排序时统一比较。

### 7.2 T8 切换点（共识时间戳 → 信任接管）

- T8 开关 OFF（计数关闭）后，防污染**由 T3 信任权重接管**（T8 §1/§5）。
- 切换点由双 PM 共管（KNET-COM-03），本文件定义运营期 T3 行为，不裁定切换时机。
