## 1. 设计动机：IM = 分布式 DNS（§0 决策）

KirinNet 的**分布式 DNS 不依赖中心化权威**（§6 去中心化原则 + §0「IM = 分布式 DNS」决策）：

- **IM 列表（contacts）即解析网络节点图**：好友关系 → 泛洪边（T1 转发关系）；本地映射表（dns_hosts）基于 IM 列表（轻量化，02 篇 FR5/NFR）。
- **双通道更新**（02 篇 FR9）：① 服务商 API（引导期依赖 + 长期并行兜底）② IM 好友消息（announce 包，去中心化解析网络）。
- **好友链泛洪解析**（02 篇 FR6）：本地 miss → 好友链受限泛洪（非广播）→ 多候选 + 权重排序。

**与去中心化纪律:** 分布式 DNS 不做根区/权威区治理、不消灭传统 DNS（并行兜底）、不向非好友广播（02 篇 §2.4 Out of Scope）。

## 2. 本地映射表（dns_hosts = IM 列表 = 解析网络，FR5）

### 2.1 dns_hosts 承载三类条目（02 篇 FR5）

- ① **好友条目**（来自 IM `announce` 包，source='friend'）
- ② **常用网址**（手动添加，source='manual'）
- ③ **泛洪应答缓存**（source='flood'）

### 2.2 条目字段（引用 T3 §2.1）

dns_hosts 字段（`domain`/`record_type`/`content`/`trust_weight`/`source`/`ttl`/`expires_at`/`via_chain`）**引用 T3 §2.1**，本文件不重定义。信任权重取值与聚合引用 T3。

### 2.3 节点轻量化（02 篇 NFR + §0 节点设计红线）

- 本地映射表基于 IM 列表，**只存好友网络相关数据 + 少量常用缓存**，非好友数据少存（节点轻量化红线）。
- 手动条目永不过期（`expires_at=NULL`）；好友/泛洪条目按 TTL 过期。

## 3. 好友链泛洪解析（FR6，引用 T1 承载）

### 3.1 解析流程（本地命中 → miss 泛洪，02 篇 §3.2 + FR6）

```
客户端 → 本节点 POST /api/dns/resolve {domain}
  │
  ├─ ① 查 dns_hosts（source ∈ manual/friend/flood）且未过期 → 聚合 → 刷新缓存 → 返回（结束）
  │
  ├─ ② miss 且 dns_flood_enabled=off → 返回 {ok:false, error:'flood_disabled'}（fail-closed）
  │
  └─ ③ 好友链泛洪（非广播，引用 T1 query/answer 包）：
        构造 query {qname, ttl:6, query_id, nonce, requester_domain, forward_chain:[self]}
        → 并行 POST 给 ≤ fanout 个未拉黑好友的 /api/dns/query（T1 承载）
        → 等待 dns_query_timeout_ms=2000ms → 聚合 answer 多候选 → 权重排序（T4）→ 写缓存 → 返回
```

### 3.2 好友节点收到 query 的行为（02 篇 §3.2 + FR6，引用 T1）

| 行为 | 说明 | 引用 |
|---|---|---|
| 限频 | 每好友入站 ≤30 次/分，超限静默丢弃 | 02 篇 FR11 / T1 §4.1 |
| 防环 | `forward_chain` 含自身域名 → 丢弃；`ttl ≤ 0` → 丢弃 | T1 §5 / FR6 |
| 本地命中 | 回传 `answer`（含 candidates[] + trust_weight + forward_chain） | T1 §3.1.4 / T4 §2 |
| 未命中 | 追加自身域名到 forward_chain，ttl-1，转发给其未拉黑好友 | T1 §4.1 |
| 均无 | 静默不响应（不回传空 answer） | T1 §6.1 / 02 篇 §3.2 |

### 3.3 关键参数（与节点 02 篇 §5.3 对齐）

| 参数 | 默认 | 说明 | 引用 |
|---|---|---|---|
| `dns_flood_enabled` | true | 好友链泛洪总开关 | 02 篇 §5.3 |
| `dns_flood_max_hops` | **6** | **六度分隔跳数上限**（传输拓扑层参数，**非社交信任链算法**） | 02 篇 FR6/§5.3 / T1 §4.1 |
| `dns_flood_fanout` | **16** | 单次泛洪最大转发好友数 | 02 篇 FR6/§5.3 / T1 §4.2 |
| `dns_flood_quota_daily` | **3** | 每日用户自主泛洪配额（超限自动拉黑 -127） | 02 篇 FR11 / T1 §8 / T3 §6 |
| `dns_query_timeout_ms` | **2000** | 泛洪等待窗口（毫秒） | 02 篇 FR6/§5.3 |
| `dns_stale_fallback` | true | miss 回退最近已知值 | 02 篇 FR10/§5.3 |

## 4. 六度分隔可达性声明（机制留阶段二预研）

### 4.1 波 0 仅声明可达性目标（传输拓扑层）

- **波 0 声明:** 好友链泛洪解析在 `max_hops=6` 跳数上限内可达好友网络内的任意域名（传输拓扑层可达性）。
- **`max_hops=6` 是传输拓扑层参数**（跳数上限），**非**社交信任链算法（KNET-CC-001 会签结论）。

### 4.2 阶段二社交信任链机制（不提前定型）

> **「六度分隔机制 = 阶段二预研，本草案不含」**

- **阶段二社交信任链算法**（如基于社交图的可达性证明、信任传播算法、六度分隔的概率可达性模型）**不在波 0 定型**，留 **PR-DDNS（波 2 预研岗）** 研究。
- 本草案**仅**承诺：`max_hops=6` 作为传输层跳数上限保证泛洪可达性；社交信任链的语义增强（如信任传播、社交图分析）是阶段二课题。

### 4.3 预研占位（PR-DDNS 波 2）

- 本草案为阶段二社交信任链**预留接口位**（`max_hops` 参数 + forward_chain 结构 + T3 权重携带），但**不定型算法**。
- PR-DDNS 波 2 在本草案契约基线上研究社交信任链增强，符合 KNET-CC-001「阶段二社交信任链不提前定型」。

## 5. 缓存与 TTL（FR10）

### 5.1 解析缓存（dns_resolve_cache，02 篇 FR10）

- `dns_resolve_cache`：`qname → candidates JSON + expires_at + last_queried`（候选 JSON schema 引用 T4 §2）。
- **TTL 取候选最小 TTL**（默认 `dns_cache_ttl=300s`，02 篇 FR10）。
- **过期保留供 stale 回退**（`dns_stale_fallback=true`，stale data > no data，02 篇 FR10）。

### 5.2 缓存清理（02 篇 FR10）

- 惰性清理（查询时检查过期）+ 每日清理过期行。

### 5.3 stale 回退（fail-open 但有界）

- 缓存过期且泛洪无应答时，回退最近已知值（stale data > no data）。
- **stale 回退有界:** 回退的 stale 候选须标注 `stale=true` 供客户端知情（防静默采信过期数据）；-127 黑名单候选**不参与** stale 回退（守 fail-closed）。
