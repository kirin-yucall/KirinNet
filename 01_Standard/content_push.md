## 1. 设计动机与原则（需求变更后的内容分发模型）

### 1.1 模型总述

```
┌─────────────────┐  ① 定向推送链接卡片（HTTP POST，非泛洪扩散）   ┌─────────────────┐
│   内容节点       │ ───────────────────────────────────────────▶ │   展示节点（极轻） │
│  alice.example  │                                               │  bob.example    │
│                 │  ② 只存卡片：title/summary/缩略图链接/签名       │  不存内容本体     │
│  内容本体+内广告 │                                               │  不掺和广告      │
│  数据主权在此     │ ◀───────────────────────────────────────────  │                 │
└─────────────────┘  ③ 点击卡片 → 新开页面跳回内容节点（落地页广告   └─────────────────┘
                        在内容节点自己的内容里展示）
```

**本质转变**（§COM-01 2026-08-09）：从「爬虫主动爬取 + 本地索引」（06 篇，已下线）改为「定向推送链接 + 展示节点轻卡片 + 跳转回内容节点」。**数据主权在内容节点**：内容、内嵌广告、访问统计全部留在创作者手里；展示节点只持有可验签的轻卡片。

### 1.2 协议原则（甲方口径逐条落协议语义）

| # | 甲方口径 | 协议落点 |
|---|---|---|
| P1 | 推送的是**链接**，非内容本体 | §3 链接卡片：payload 仅含 title/summary/thumbnail_url/content_key 等定位与摘要字段，无内容体 |
| P2 | 展示节点**极轻** | §5.4：展示节点禁止拉取/缓存/解析内容本体；卡片 JSON ≤2 KiB；缩略图可选直链加载或禁用 |
| P3 | 点击**新开页面跳回内容节点** | §6：跳转 URL 由 `creator_domain + content_key` 构造；新开标签页（`noopener`）；禁止 iframe/代理/包装 |
| P4 | **广告留在内容节点** | §6.3：展示节点 MUST NOT 注入、包装或在跳转链路掺和广告；落地页内广告由内容节点自主呈现 |
| P5 | **抗屏蔽** | §7：屏蔽 = 展示节点本地 opt-out（拒收 + 本地下架），无全网删除义务，不影响其他节点展示 |
| P6 | 节点自身可有**广告位** | §8：`ad_slot` 卡片（复用链接卡片结构 + `slot_id`），链接来自其他节点投放或商业链接 |
| P7 | 节点间广告波 1 只做**友情展现** | §8.3：免费互换投放；`price_hint` 恒 `null` 留接口字段，付费语义**不定型**（付费结算后定） |
| P8 | 爬虫探索下线，探索发现改走泛洪 | 定向推送与 T1 泛洪公告互补（§2）；本文件不涉及探索发现机制（06 篇已下线，不引用） |

### 1.3 与去中心化纪律的关系

- 定向推送是**点对点 opt-in 关系**（内容节点 → 明确选定的展示节点），不是广播、不依赖中心索引/爬虫/注册系统。
- 防滥用是**接收方本地行为**（黑名单 opt-out + 入站限频），无中心化限流网关——与 T1 §8「配额与限频是节点本地行为」同一纪律。
- 身份与防伪依赖 **did:dns 三记录 + Ed25519**（did-dns §2，TXT 全量 `did:dns:`，统一 Ed25519 红线），身份记录解析**强制 DoH/DoT，禁明文 53**（架构红线）。

## 2. 与 T1 泛洪协议的关系（`publish` 的直达变体）

### 2.1 归属声明

T1（`flood_protocol.md`）§3 已明文：`publish`（内容发布泛洪）的**语义由内容发布域定义，T1 仅定义信封承载位**。本文件即该内容发布域的语义主笔：定义 `publish` 的两种投递形态（delivery）。

### 2.2 两种投递形态

| 形态 | `payload.delivery` | 通道 | ttl | forward_chain | 转发义务 | 泛洪配额 | 状态 |
|---|---|---|---|---|---|---|---|
| **直达（direct）** | `"direct"` | 点对点 HTTPS `POST /api/v2/push/card`（§9） | **恒 1** | **恒 `[src_domain]`**（单元素） | **无**（接收方 MUST NOT 转发） | **不计**（非好友链扩散） | **波 1 主形态**（本文件定稿依据） |
| 泛洪（flood） | `"flood"` | 好友链受限泛洪（T1 §3 `publish` 原义） | ≤6（T1 §4.1） | 链式追加（T1 §5） | 有（T1 转发规则） | **计入每日 3 次**（T1 §8） | 节点泛洪引擎就绪后启用（fail-closed，引擎未实现前不得启用） |

### 2.3 直达变体的语义叠加（不改 T1 任何字段定义）

本文件对 T1 信封（§2 公共字段）**零改动、零重定义**，仅施加定向约束：

1. `type` 恒为 `"publish"`（复用 T1 §3 包类型枚举，不新增类型）；
2. `ttl` 恒为 `1`：接收方校验 `ttl ≠ 1` → 拒收（fail-closed，防直达包被误作泛洪包扩散）；
3. `forward_chain` 恒为 `[src_domain]`（单元素）：链长 ≠1 → 拒收；
4. 接收方 **MUST NOT 转发**直达包（无扩散义务；转发即违反定向语义）；
5. 直达推送**不计入** T1 §8 每日 3 次泛洪配额（该配额约束好友链扩散；直达是点对点请求，防滥用由接收方本地限频/黑名单承担，§5.2/§7）；
6. `nonce`/`query_id` 沿用 T1 §2.1 语义（防重放去重），挑战码结构**引用 T9 §9.3.1**；
7. `signature` 覆盖范围**引用 T9 §9.3.2**（挑战码 + 双方域名 + `forward_chain`；第 5 项 `trust_weight` 不适用——本包不携带权重字段），算法/规范化归 T9，本文件不重定义。

> **依据对照:** 节点仓 10 篇 FR4 的现行实现（push.js：DoH 解析目标域名 + `/health` 探活 + POST metadata 到目标索引）即直达形态的雏形；本文件将其契约化为 `delivery:"direct"`。

## 3. 链接卡片格式（link card）

### 3.1 结构

```
{
  "v": 1,
  "card_type": "content",
  "title": "<标题, UTF-8, 1~120 字符>",
  "summary": "<摘要, UTF-8, 0~300 字符>",
  "thumbnail_url": "<HTTPS 缩略图直链 | null>",
  "creator_domain": "<内容节点域名, ASCII>",
  "content_key": "<内容定位键, ASCII>",
  "content_type": "<article | product | post | video>",
  "iat": <卡片签发时间, Unix 秒>,
  "exp": <卡片过期时间, Unix 秒>,
  "creator_fp": "<creator_domain 的 did:dns 公钥指纹, 16 字符>",
  "creator_sig": "<Ed25519 卡片签名, Base64URL>"
}
```

> 风格对齐 did-dns §2 三记录（简洁、单条轻量、自包含可验）。卡片 JSON 序列化后 **MUST ≤ 2 KiB**（请求体整体 ≤ 8 KiB，对齐节点侧 F01 解密端点 body 上限口径）。

### 3.2 字段定义

| 字段 | 类型 | 必选 | 约束 | 含义 |
|----|------|------|------|------|
| `v` | int | 是 | 固定 `1` | 卡片格式版本 |
| `card_type` | enum | 是 | `content` / `ad_slot`（§8） | 内容卡片 / 广告位卡片 |
| `title` | str | 是 | UTF-8，1~120 字符 | 卡片标题（展示节点列表/搜索主字段） |
| `summary` | str | 否 | UTF-8，0~300 字符 | 摘要（展示节点可直接呈现，不抓取内容） |
| `thumbnail_url` | str/null | 否 | HTTPS URL，≤512 字符；`null` = 无缩略图 | 缩略图**直链**（存链接不存图）；展示节点可策略性禁用加载（§5.4） |
| `creator_domain` | str | 是 | ASCII 域名，≤253 字符，与信封 `src_domain` **必须一致** | 内容节点域名（did:dns:v=1 身份锚点，跳转目标域） |
| `content_key` | str | 是 | ASCII `[A-Za-z0-9._~-]{1,128}`（RFC 3986 unreserved，禁 `/ ? # & %` 等保留字符——防跳转 URL 路径注入） | 内容定位键（内容节点内唯一，如内容 ID/slug） |
| `content_type` | enum | 是 | `article` / `product` / `post` / `video`（对齐节点仓 05/12 篇 content_type 基线；`ad_slot` 卡片恒为 `ad`，§8.2） | 内容类型（展示节点分类浏览依据） |
| `iat` | int | 是 | Unix 秒；接收时刻偏差 MUST ≤ ±5 分钟（对齐 did-dns §3.3 第 4 条新鲜度，防旧卡重放） | 卡片签发时间 |
| `exp` | int | 是 | Unix 秒；MUST `exp > iat`；建议 `exp − iat ≤ 90 天`（`ad_slot` 建议 ≤30 天），到期后展示节点本地下架（§5.5） | 卡片有效期（**卡片**有效期，非内容有效期——内容生命周期归内容节点） |
| `creator_fp` | str | 是 | 16 字符 = `Base64URL(SHA-256(公钥)[0:12])`（**引用 did-dns §2.1 fp 定义，不重定义**） | 绑定 creator_domain 的 did:dns:v=1 身份声明指纹；接收方验签时比对，防旧钥/他钥冒名 |
| `creator_sig` | str | 是 | Ed25519 签名 64 字节 Base64URL（约 86 字符），生成规则见 §4.3 | 卡片级签名：证明卡片确由 creator_domain 持钥者签发（防伪造卡片）；卡片存储后可独立重验 |

### 3.3 卡片定位与幂等键

- 全网唯一定位：`(creator_domain, content_key)` 二元组。
- 展示节点以该二元组作 **upsert 幂等键**：同键重推 = 更新卡片（标题/摘要/缩略图/新 iat/exp/新签名），非重复收录（§9.3 响应 `updated:true`）。
- 删除/下线语义：内容节点重推同键卡片即覆盖；协议**不提供跨节点撤回原语**（抗屏蔽语义，§7）。

## 4. 定向推送包（wire 格式）

### 4.1 整体结构

```
POST https://<展示节点域名>/api/v2/push/card
Content-Type: application/json

{
  "v": 1,                                    ← T1 信封（引用 §2，不重定义）
  "type": "publish",
  "src_domain": "alice.example",
  "ttl": 1,
  "query_id": "<发送方生成随机标识, ASCII ≤64>",
  "nonce": "<挑战码 nonce:timestamp:hmac, 引用 T9 §9.3.1>",
  "forward_chain": ["alice.example"],
  "signature": "<信封签名, 覆盖引用 T9 §9.3.2>",
  "payload": {
    "v": 1,
    "delivery": "direct",
    "target_domain": "bob.example",
    "card": { ...链接卡片, §3... }
  }
}
```

- 信封字段（`v`/`type`/`src_domain`/`ttl`/`query_id`/`nonce`/`forward_chain`/`signature`）**全部引用 T1 §2.1 定义**，本文件不重定义；定向约束见 §2.3。
- `payload.delivery`/`payload.target_domain` 为本文件新增（payload 归内容发布域主笔，T1 仅承载）。
- `payload.target_domain` = 接收方（展示节点）域名：① 供接收方核对 HTTP 目标与签名一致；② 纳入卡片级签名输入（§4.3），防卡片跨节点重放。

### 4.2 两层签名的分工

| 层 | 字段 | 签名者 | 作用 | 覆盖范围 |
|---|---|---|---|---|
| 传输级（信封） | `signature` | 发送方节点（Ed25519 节点身份钥） | 防传输重放（nonce 一次性）+ 绑定双方域名 + 防转发链篡改 | **引用 T9 §9.3.2**（挑战码 / 校验方域名=target / 受验方域名=src / forward_chain；第 5 项权重不适用） |
| 卡片级 | `card.creator_sig` | 内容创作者（creator_domain 持钥者） | **防伪造卡片** + 卡片离线可验（存储后与传输会话解耦，任何持 did:dns:pk 者可独立重验） | 本文件 §4.3 定义（新契约，非 T9 修订） |

> 卡片级签名独立存在的理由：卡片被展示节点**长期存储**并对外呈现，其可验证性必须自包含（不依赖推送时刻的传输会话）；且广告位互换（§8）与未来的代理投递形态下，信封发送方与卡片创作者可能分离，两层签名权责清晰。

### 4.3 卡片级签名（creator_sig）生成与验证

**签名输入**（固定顺序、`\n` 分隔；JSON 规范化**沿用 T9 §9.3.2 规则**——JCS（RFC 8785）后签名，禁止字段重排/省略后签名）：

```
sign_input = JCS(card 除 creator_sig 外的全部字段) + "\n" + payload.target_domain
```

- 签名算法：Ed25519（64 字节，Base64URL）——统一 Ed25519 红线（DECISIONS §9.2.3）。
- `target_domain` 纳入输入：卡片绑定接收节点，**防跨节点卡片重放**（为节点 B 签的卡片不能被转投节点 C；内容节点向 N 个展示节点推送时逐个签发，成本可忽略）。
- 验证（接收方/任何重验者）：
  1. DoH/DoT 解析 `creator_domain` TXT → `did:dns:v=1`（校验 `iat` ±5min、`fp ∉ black`）→ `did:dns:pk`（`kty=ed25519`）→ `did:dns:black`（**引用 did-dns §2/§3 记录与校验规则，不重定义**）；
  2. 比对 `card.creator_fp == did:dns:v=1 的 fp`；
  3. 以 `did:dns:pk` 公钥验 `creator_sig`。
- DNSSEC 可用时应校验（did-dns §2.1 建议）；无 DNSSEC 时以 DoH/DoT 加密通道 + 指纹链兜底（与 did-dns §5 威胁模型一致）。

## 5. 展示节点行为（接收 → 校验 → 存储 → 展示）

### 5.1 接收流程总览

```
① 传输与信封校验（§5.2）
② 卡片校验（§5.3，任一步失败 → fail-closed 拒收，不静默收录）
③ 黑名单 opt-out 检查（§7）
④ 存储：卡片原文 + 验签元数据（§5.4，极轻）
⑤ 展示：列表/搜索/滑动仅基于卡片字段（§5.5）
⑥ 点击：新开页面跳转内容节点（§6）
```

### 5.2 传输与信封校验

| # | 校验项 | 失败处置 |
|---|---|---|
| 1 | HTTPS（强制；身份记录解析 DoH/DoT，禁明文 53） | 拒绝（传输层红线） |
| 2 | 信封结构完整（T1 §2 字段齐全、类型正确）、`v=1`、`type="publish"` | 400 `invalid_envelope` |
| 3 | `ttl == 1` 且 `forward_chain == [src_domain]`（§2.3 定向约束） | 400 `not_direct_form` |
| 4 | `payload.delivery == "direct"`、`payload.target_domain == 本节点域名` | 400 `target_mismatch` |
| 5 | `query_id + nonce` 去重表未命中（T1 §5.2 防重放；命中即重放包） | 409 `replayed`（节点 PM 会签裁定**统一 409**，幂等重放，§9.3） |
| 6 | 信封 `signature` 验签（覆盖引用 T9 §9.3.2；公钥 = DoH/DoT 解析 `src_domain` 的 `did:dns:pk`） | 400 `bad_signature` |
| 7 | 入站限频：每 `src_domain` ≤30 次/分（对齐节点 02 篇 FR11 入站限频口径，本地策略） | 429 `rate_limited` |

### 5.3 卡片校验（fail-closed）

| # | 校验项 | 失败处置 |
|---|---|---|
| 1 | 字段完整/类型/长度（§3.2 约束逐项：title≤120、summary≤300、content_key 字符集、卡片 ≤2 KiB 等） | 400 `invalid_card` |
| 2 | `card.creator_domain == 信封 src_domain`（直达形态下推送方即创作者；本版不支持代理投递） | 400 `creator_mismatch` |
| 3 | `iat` 接收时刻偏差 ≤±5 分钟；`exp > iat`；未过期 | 400 `stale_card` / `expired_card` |
| 4 | `content_type` 枚举合法（`ad_slot` 卡片走 §8 附加校验） | 400 `invalid_card` |
| 5 | did:dns 三记录校验（DoH/DoT 解析 creator_domain：v=1 新鲜度 ±5min、pk kty=ed25519、fp∉black） | 400 `creator_dns_invalid` |
| 6 | `creator_fp` == v=1 记录的 `fp`；`creator_sig` 验签（§4.3） | 400 `bad_creator_sig` |

> **fail-closed 红线：** 任一校验失败即拒绝收录（4xx 明确响应）；**禁止**「先收录后补验」或「验不过仍暂存」。（修复节点仓 12 篇已知缺陷 7.1——原 publish 无签名校验只存不验，可伪造 creator_domain 灌数据。）

### 5.4 存储（极轻清单）

| MUST（禁止项） | 说明 |
|---|---|
| **不拉取内容本体** | 仅存卡片；不得回源抓取 `content_key` 指向的页面/文件 |
| **不缓存缩略图文件** | `thumbnail_url` 存直链；加载与否由展示节点本地策略（隐私/流量），禁改写为本地代理图床 |
| **不解析/索引内容文本** | 搜索仅基于卡片 title/summary（对齐 12 篇「不做搜索排名算法」边界） |
| **不修改卡片语义字段** | title/summary/content_key/跳转 URL 原样呈现（本地仅 `is_listed` 上下架开关） |

存储建议（实现细节归节点 PM，§10 给出表列映射）：存卡片 JSON 原文（含 `creator_sig`，自包含可重验）+ 验签元数据（`creator_fp`/接收时间）+ 本地展示开关 + 点击计数。

### 5.5 展示与生命周期

- 列表/搜索/滑动/趋势：仅基于卡片字段（title/summary/content_type/iat/点击数）——12 篇原有检索/滑动体验对卡片数据源平移（数据源由「爬取/被动聚合」改为「定向推送收录」）。
- 点击：§6 跳转；点击计数 +1（本地点击数，非内容访问量——内容访问统计在内容节点）。
- 过期：`exp` 到期 → 本地下架（`is_listed=false`），已存记录保留（创作者重推同键新卡即恢复展示）。
- 黑名单：§7 opt-out。

## 6. 跳转与广告边界

### 6.1 跳转 URL 构造（creator_domain + content_key）

```
jump_url = "https://" + creator_domain + "/view/" + content_key
```

- 该规则是**跨仓契约**：内容节点（creator_domain 侧）MUST 提供 `GET /view/<content_key>` 公开内容页（未认证可读、移动端可用）；`content_key` 字符约束（§3.2）保证构造无歧义。
- 波 1 过渡：内容节点暂无独立 `/view/` 页时，可暂以其 SPA 内路由承接（如 `/app#/view/<content_key>`），但**定稿口径以 `/view/<content_key>` 为准**（KNET-CC-012 会签时节点 PM 确认落地路径）。
- 展示节点 MUST 新开页面（`target="_blank"` + `rel="noopener noreferrer"`）。
- creator_domain 端点解析（SRV 发现/多候选/direct→relay 回退/NAT 后仅 relay）**引用 T4 与 spec_v1 §3.1**，本文件不重定义；浏览器直跳场景按标准 DNS+HTTPS 即可。

### 6.2 点击行为约束

| MUST NOT | 理由 |
|---|---|
| 不得 iframe/反代/包装内容页 | 内容与广告主权在内容节点（P4） |
| 不得在跳转前插中间页/倒计时/自家广告 | 同上 |
| 不得篡改 jump_url（加参数跟踪除外，须本地策略明示） | 卡片语义原样呈现 |

### 6.3 广告边界（广告留在内容节点）

- 内容内广告：在内容节点落地页自己的内容里展示，展示节点**不掺和**（不注入、不分成、不感知）。
- 展示节点自身的广告位（站内广告位卡片）是**独立机制**（§8），与所展示的内容卡片互不掺杂：广告位是节点自己的版面经营，内容卡片是替其他节点呈现的链接。

## 7. 抗屏蔽语义（屏蔽 = 接收方 opt-out）

### 7.1 三原则（MUST）

| # | 原则 | 协议语义 |
|---|---|---|
| 1 | **屏蔽是接收方本地 opt-out** | 展示节点将 `creator_domain` 加入本地 `push_blacklist` → ① 后续该域名推送 403 拒收；② 已收录卡片本地下架（`is_listed=false`）。仅此而已 |
| 2 | **不产生全网删除义务** | 屏蔽节点的处置对其他节点**无任何效力**；协议不提供跨节点删除/撤回原语（§3.3）；无全局索引可被要求清理 |
| 3 | **不阻止其他节点展示** | 内容在创作者手里（内容节点），卡片经其他展示节点继续呈现；内容节点可同时向任意多个展示节点定向推送，被部分屏蔽不影响其余链路 |

### 7.2 与既有黑名单机制的关系（不合并、不重定义）

| 机制 | 层 | 归属 | 效力范围 |
|---|---|---|---|
| `push_blacklist`（12 篇，表已保留） | 展示/收录层 | 本文件 §7 | 本节点拒收+下架该创作者卡片 |
| T3 `-127` 黑名单（IM/解析层） | 好友链全链路 | **引用 T3 §6，不重定义** | 本节点不转发其泛洪包、不响应其查询 |

两层独立生效、互不替代（站长可只用其一）；合并与否留节点侧实现策略，本文件不定。

## 8. 节点广告位（波 1：友情展现）

### 8.1 模型

节点自身版面可设广告位（slot）：**链接来自其他节点投放**（友情互换，免费）或商业链接（08/09 篇商业线，节点侧自理，不在本协议范围）。波 1 节点间广告只做**友情展现**——免费互换投放，无结算。

### 8.2 广告位卡片（ad_slot，复用链接卡片结构 + slot 标识）

```
{
  "v": 1,
  "card_type": "ad_slot",
  "slot_id": "<目标节点广告位标识, ASCII [a-z0-9-]{1,32}, 如 home-top / sidebar-1>",
  "title": "<广告标题, 1~120 字符>",
  "summary": "<广告摘要, 0~300 字符>",
  "thumbnail_url": "<素材直链 | null>",
  "creator_domain": "<投放方（内容）节点域名>",
  "content_key": "<落地页定位键>",
  "content_type": "ad",
  "price_hint": null,
  "iat": ..., "exp": ...,
  "creator_fp": "...",
  "creator_sig": "..."
}
```

- 与内容卡片的差异仅 3 处：`card_type="ad_slot"`、新增 `slot_id`（投放目标位标识，由展示节点对外公布）、`price_hint`（§8.3）。
- `content_type` 恒 `"ad"`（落地页具体形态不影响广告位展示）。
- 校验/签名/存储/跳转**完全复用** §4~§6 契约（同一验签链、同一跳转构造）；`exp − iat` 建议 ≤30 天（友情位短周期互换）。
- `ad_slot` **附加校验**（`slot_id` 格式 `[a-z0-9-]{1,32}`、`content_type` 恒 `"ad"`、`price_hint` 恒 `null` 等 §8 约束）失败 → **400 `invalid_slot`**（错误码与 §9.3 枚举对应；区别于 §5.3 通用卡片校验失败的 `invalid_card`）。
- 广告点击后落地页及其广告归投放方节点（同 §6.3 边界）。

### 8.3 付费投放：留接口不定型（守「付费结算后定」口径）

- `price_hint` 字段**恒 `null`**（MUST）：为付费投放预留的接口字段，波 1 无语义。
- 发送方 MUST 置 `null`；接收方 MUST 忽略其值（出现非 `null` 值不构成任何报价/要约/结算依据，也不得据此拒收——字段值被无条件忽略）。
- 付费投放的计费/结算/对账语义**待付费体系裁决后另立草案**（届时经 KNET-CC 修订本文件），本文件不预设任何付费模型。

### 8.4 友情互换投放端点

- 投放走 §9.2 端点 `POST /api/v2/push/adslot`（与内容卡片同族、分开端点便于节点分别开关）。
- 互换是**双边自愿**：A 节点向 B 投放不产生 B 向 A 投放的义务；接收方对 ad_slot 卡片的拒收/下架自由度同 §7 opt-out。
- 展示节点对外公布可用 `slot_id` 清单的方式（端点/页面）由节点侧自理，本文件不定。

## 9. 端点契约（统一口径）

### 9.1 现状勘误（为何必须统一）

| 旧路径 | 现状 | 结论 |
|---|---|---|
| `POST /api/v1/publish`（push.js:80/191 现推路径） | **从未存在**（节点仓已知 bug，10 篇缺陷 7.4：push.js 目标端点与本地实现不符） | 废弃 |
| `POST /api/indexer/publish`（原接收端，indexer.js） | **已下线删除**（2026-08-09 废弃处置 commit 0698512：indexer.js 被动聚合层与 indexed_content/ingestion_log 表一并移除） | 废弃 |

两条旧路径均不可用；本节给出**统一新口径**，作为 KNET-CC-012 会签依据（端点路径变更属跨仓契约）。

### 9.2 端点定义

| 端点 | 用途 | 认证 | 实现 |
|---|---|---|---|
| `POST /api/v2/push/card` | 接收**内容链接卡片**定向推送（请求体 = §4.1 定向推送包） | 无用户级认证（身份=两层签名，§4.2；本地黑名单/限频防滥用） | 波 1 **必选** |
| `POST /api/v2/push/adslot` | 接收**广告位卡片**友情投放（请求体 = §4.1，card 为 §8.2 ad_slot 卡） | 同上 | 波 1 可选（节点未开广告位可 404） |

- 命名进入 `/api/v2/` 命名空间：与两条已废弃 v1/indexer 路径彻底切割，避免旧路径兼容负担。
- 发送方流程（push.js 演进依据，10 篇 FR4 契约化）：DoH 解析目标域名（强制加密 DNS）→ `GET /health` 探活 → 逐目标构造 §4.1 推送包（`target_domain` 逐个签发卡片，§4.3）→ POST。

### 9.3 响应契约

| 状态码 | 场景 | 响应体 |
|---|---|---|
| 200 | 收录成功 / 幂等重推更新 | `{"status":"accepted","card_id":<本地ID>,"updated":<bool>}`（`(creator_domain,content_key)` 命中已有记录 → upsert，`updated:true`） |
| 400 | 校验失败（§5.2/§5.3 各项，fail-closed 明确拒因） | `{"error":"<invalid_envelope|not_direct_form|target_mismatch|bad_signature|invalid_card|creator_mismatch|stale_card|expired_card|creator_dns_invalid|bad_creator_sig|invalid_slot>","detail":"..."}` |
| 409 | 防重放命中（§5.2 第 5 项：`query_id + nonce` 已见于去重表，节点 PM 会签裁定**统一 409**） | `{"error":"replayed"}`（幂等重放：重放包不重复收录、不触发 upsert 更新；与 200 `updated:true` 的同键新信封重推区分） |
| 403 | 黑名单 opt-out（§7） | `{"error":"blacklisted"}` |
| 404 | 端点未启用（展示功能关闭 / 未开广告位） | `{"error":"not_enabled"}` |
| 429 | 入站限频（§5.2 第 7 项） | `{"error":"rate_limited","retry_after_ms":<ms>}` |
| 503 | 节点未就绪（未初始化等） | `{"error":"not_ready"}` |

## 12. 安全考量汇总（fail-closed）

| 威胁 | 缓解 | 落点 |
|---|---|---|
| 伪造卡片（冒名 creator_domain） | `creator_sig` + did:dns fp 指纹链 + DoH/DoT 解析 | §4.3、§5.3-5/6 |
| 卡片跨节点重放 | `target_domain` 纳入卡片签名输入 | §4.3 |
| 传输重放 | 信封 `nonce` 一次性去重 + `iat` ±5min 新鲜度 | §5.2-5、§5.3-3（引用 T9 §9.3.1） |
| 投毒/灌数据（缺陷 7.1 复发） | fail-closed 全量校验，验不过不收录；入站限频 30/分/源 | §5.3、§5.2-7 |
| 中间人 | 强制 HTTPS + 强制 DoH/DoT（禁明文 53） | §5.2-1 |
| 旧钥/泄露钥签名 | `did:dns:black` 黑名单校验 + `creator_fp` 比对 | §5.3-5 |
| 跳转 URL 注入 | `content_key` 字符集白名单（RFC 3986 unreserved） | §3.2 |
| 卡片超载/巨型包 | 卡片 ≤2 KiB、请求体 ≤8 KiB、字段长度上限 | §3.1/§3.2 |
| 缩略图外链隐私 | 直链可选加载，展示节点可禁用 | §5.4 |

> **去中心化纪律:** 上述防线全部为**接收方本地行为**（验签/限频/黑名单/长度约束），无中心化网关、无注册、无 CA——与 T1 §8 同一纪律。
